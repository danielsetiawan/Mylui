## 4. Arsitektur

```
Browser
  └─ React SPA
       ├─ Context Providers (state global, fetch saat user login)
       ├─ Pages (masing-masing memanggil Supabase langsung, tanpa layer service/repository)
       └─ supabase-js ──HTTPS──► Supabase (PostgREST + GoTrue Auth)
```

Karakteristik penting:

- **Tidak ada layer data access.** Setiap halaman menulis query `supabase.from(...)` sendiri di dalam komponen.
- **Cache data hanya di Dashboard dan Activity** lewat TanStack Query (`src/app/lib/queryClient.ts`). Halaman lain (Planning, Notes, Split Bill, Master Data, Init) masih mengambil data dengan `useEffect` setiap kali dibuka. Lihat "Cache data" di bawah.
- **Tidak ada state management library** untuk state klien. Hanya `useState` + 4 React Context.
- **Semua form "add/edit" adalah komponen yang dirender oleh halaman index**, bukan route tersendiri. File `pages/*/add.tsx`, `edit.tsx`, `detail.tsx` **bukan route**.
- **Keamanan data bergantung sepenuhnya pada RLS Supabase.** Klien selalu menambahkan `.eq('user_id', user.id)` pada SELECT, tapi UPDATE/DELETE hanya memfilter `id`. Isi policy RLS **[TIDAK DIKETAHUI]** — tidak ada file SQL/migration di repo.
- **Operasi multi-tabel tidak atomik** (tidak ada RPC/transaction). Header di-insert dulu, lalu detail; jika langkah kedua gagal, data setengah jadi tertinggal.

### Urutan Provider (`src/app/App.tsx`)

```
QueryClientProvider             (cache TanStack Query)
  └─ AuthProvider
       └─ MonthRangeProvider        (butuh useAuth)
            └─ WalletCategoryProvider (butuh useAuth)
                 └─ VisibilityProvider
                      ├─ <Toaster position="bottom-center" richColors />
                      └─ <RouterProvider router={router} />
```

Urutan ini wajib dipertahankan: `MonthRangeProvider` dan `WalletCategoryProvider` memanggil `useAuth()`.

### Cache data (`src/app/lib/queryClient.ts`)

- `staleTime: 0`, `gcTime` 30 menit, `retry: 1`. Artinya: saat halaman dibuka lagi, data cache **langsung tampil**, lalu diambil ulang di belakang layar. Data juga diambil ulang saat tab browser kembali difokuskan (perilaku default TanStack Query).
- **Semua query key dari tabel `transactions` diawali `['transactions', userId]`** (lihat `queryKeys`). Setelah tambah/ubah/hapus transaksi, halaman Activity memanggil `invalidateQueries({ queryKey: queryKeys.transactions(userId) })` sehingga daftar, statistik, dan Dashboard ikut diperbarui. Kode baru yang menulis ke `transactions` sebaiknya melakukan hal yang sama.
- Halaman lain yang menulis ke `transactions` (`Init.tsx`) **tidak** meng-invalidate; data baru muncul karena `staleTime: 0` memicu pengambilan ulang saat halaman dibuka.
- `fetchAllRows(build)` mengambil semua baris sebuah query per 1000 baris (batas default PostgREST), dipakai untuk penjumlahan di klien.
- Cache dikosongkan (`queryClient.clear()`) saat sesi berakhir, di `AuthContext`.
- Skeleton (`animate-pulse`) hanya tampil saat belum ada data sama sekali (`isPending`), bukan saat pengambilan ulang.

## 5. Routing (`src/app/routes.tsx`)

Semua halaman di-load dengan `React.lazy` (satu chunk per halaman). Fallback `<Suspense>` untuk halaman di dalam Layout ada di `layouts/Layout.tsx`; `/login` punya `<Suspense>` sendiri di `routes.tsx`. Setelah event `load`, chunk halaman lain diunduh di belakang layar (`requestIdleCallback`) supaya navigasi berikutnya tidak menunggu unduhan.

| Path | Komponen | File | Akses |
|---|---|---|---|
| `/login` | `Login` | `pages/Login.tsx` | Publik. Jika sudah login → redirect ke `/` |
| `/` | `Dashboard` | `pages/Dashboard.tsx` | Login |
| `/transactions` | `Transactions` | `pages/transactions/index.tsx` | Login |
| `/planning` | `Planning` | `pages/planning/index.tsx` | Login |
| `/notes` | `Notes` | `pages/Notes.tsx` | Login |
| `/split-bill` | `SplitBill` | `pages/split-bill/index.tsx` | Login |
| `/split-bill/new` | `SplitBillAdd` | `pages/split-bill/add.tsx` | Login. Harus didaftarkan sebelum `:id` |
| `/split-bill/:id` | `SplitBillEdit` | `pages/split-bill/edit.tsx` | Login. Memuat bill dari DB berdasarkan id; id tidak ditemukan → toast + kembali ke list |
| `/master-data/wallets` | `WalletsPage` | `pages/master-data/WalletsPage.tsx` | Login |
| `/master-data/categories` | `CategoriesPage` | `pages/master-data/CategoriesPage.tsx` | Login |
| `/init` | `Init` | `pages/Init.tsx` | Login + `profile.role === 'admin'` (dicek di dalam komponen, bukan di router) |
| `*` | `<Navigate to="/" replace />` | — | — |

Hirarki: `AuthGuard` (cek sesi) → `Layout` (shell) → halaman. Semua route selain `/login` ada di bawah `AuthGuard`.

`AuthGuard` (`components/AuthGuard.tsx`): saat `loading` tampilkan logo beranimasi "Memuat aplikasi..."; jika `user` null → `<Navigate to="/login">`; selain itu `<Outlet/>`.

### Navigasi (`layouts/Layout.tsx`)

- **Lebar konten**: `<main>` di `Layout.tsx` membungkus halaman dengan `max-w-7xl mx-auto p-4 md:p-8 xl:px-12` (diperlebar dari `max-w-5xl` pada 2026-11-22 atas permintaan pemilik). Halaman Wallets, Categories, dan Init sengaja tetap sempit di tengah lewat `max-w-2xl`/`max-w-4xl` milik halaman itu sendiri.
- **Desktop (≥ `md`)**: sidebar kiri — Dashboard, Activity (`/transactions`), Planning, Notes, Split Bill, bagian "Master Data" (Wallets, Categories), dan "Init Data" (hanya admin). Tombol Sign Out di bawah.
- **Mobile (< `md`)**: header atas (logo, sapaan, tombol hide-amount, edit profile, tema, logout) + bottom nav melayang berisi 6 item: Home, Activity, Plans, Notes, Split, **More**.
- Tombol **More** membuka menu kecil di atas bottom nav (state `showMore` di `Layout.tsx`, komponen `MoreMenuItem`) berisi Wallets, Categories, dan Init Data (hanya admin). Menu tertutup otomatis saat pindah halaman; tombol More tampil aktif saat berada di `/master-data/*` atau `/init`. **Halaman baru yang tidak muat di bottom nav ditambahkan ke menu ini.**
- Layout juga memuat: toggle tema, toggle sembunyikan nominal, modal "Edit Profile" (update `profiles.full_name`).
- Label "Activity" di UI = entitas `transactions` di kode/DB. Istilah "Transaction" dan "Activity" dipakai bergantian.

## 6. State Global (Context)

### 6.1 `AuthContext` — `contexts/AuthContext.tsx`

Hook: `useAuth()` (throw jika di luar provider).

| Field | Tipe | Keterangan |
|---|---|---|
| `user` | `User \| null` | User Supabase Auth |
| `session` | `Session \| null` | |
| `profile` | `Profile \| null` | Baris tabel `profiles` dengan `id = user.id` |
| `loading` | `boolean` | `true` sampai event auth pertama diterima |
| `signIn(email, password)` | → `{ error }` | `auth.signInWithPassword` |
| `signUp(email, password, fullName)` | → `{ error }` | `auth.signUp` dengan `options.data.full_name` |
| `signInWithGoogle()` | → `{ error }` | `auth.signInWithOAuth({ provider: 'google', redirectTo: window.location.origin })` |
| `signOut()` | | |
| `refreshProfile()` | | Fetch ulang `profiles` |

Cara kerja: hanya berlangganan `supabase.auth.onAuthStateChange` (tidak memanggil `getSession()`; mengandalkan event `INITIAL_SESSION`). `setUser`/`setSession` hanya mengganti referensi jika `id`/`access_token` berubah, supaya context lain yang bergantung pada `user` tidak re-fetch saat token refresh.

Baris `profiles` **tidak dibuat oleh klien**. Kode hanya SELECT dan UPDATE `full_name`. Pembuatan baris (kemungkinan trigger DB pada `auth.users`) **[TIDAK DIKETAHUI]**.

### 6.2 `MonthRangeContext` — `contexts/MonthRangeContext.tsx`

Hook: `useMonthRange()` → `{ monthOptions: {value:'yyyy-MM', label:'March 2025'}[], isLoading, refresh }`.

- Saat `user` berubah: 2 query ke `transactions` (tanggal terlama & terbaru milik user), lalu membangkitkan daftar bulan dari terbaru → terlama. Bulan berjalan selalu disertakan.
- Label berformat `en-US` (mis. "March 2025").
- Dipakai sebagai opsi dropdown filter bulan di: Transactions, TransactionAdd/Edit (pemilih bulan "Link to Income"), Planning, Notes.
- `refresh()` tersedia tapi **tidak pernah dipanggil** di mana pun → daftar bulan tidak ter-update setelah menambah transaksi di bulan baru sampai halaman di-reload.

### 6.3 `WalletCategoryContext` — `contexts/WalletCategoryContext.tsx`

Hook: `useWalletCategory()` (throw jika di luar provider).

| Field | Keterangan |
|---|---|
| `wallets: Wallet[]` | Semua wallet user, urut `created_at` ASC |
| `categories: TransactionCategory[]` | Semua kategori user, urut `name` ASC |
| `loadingWallets`, `loadingCategories` | |
| `refreshWallets()`, `refreshCategories()` | Fetch ulang dari DB |
| `addWallet(data)` | Insert + append ke state. Return `Wallet \| null` (null jika error — **error ditelan**, tanpa pesan) |
| `addCategory(data)` | Sama, untuk kategori. Item baru di-append (urutan abjad tidak dijaga sampai refresh) |

Update & delete wallet/kategori **tidak ada di context**; dilakukan langsung di `WalletsPage`/`CategoriesPage` lalu memanggil `refresh*()`.

### 6.4 `VisibilityContext` — `contexts/VisibilityContext.tsx`

Hook: `useVisibility()` → `{ amountsVisible, toggleAmounts, maskAmount(formatted) }`.

- Fitur "sembunyikan nominal". `maskAmount` mengembalikan `'••••••'` jika disembunyikan.
- Disimpan di `localStorage['amountsVisible']` (`'false'` = tersembunyi; default terlihat).
- Dipakai di: Layout (tombol mata), Dashboard, Transactions. **Tidak dipakai** di Planning, Split Bill, Init → nominal di sana tetap terlihat.

### 6.5 State lokal di `localStorage`

| Key | Nilai | Ditulis oleh |
|---|---|---|
| `theme` | `'dark'` \| `'light'` | `Layout.tsx` |
| `amountsVisible` | `'true'` \| `'false'` | `VisibilityContext` |
| `sb-<project>-auth-token` | sesi Supabase | supabase-js |

Tema: class `dark` di `<html>`; default mengikuti `prefers-color-scheme` jika `theme` belum tersimpan. Tema diterapkan oleh skrip inline di `index.html` **sebelum React render**, jadi berlaku di semua halaman termasuk `/login` dan tanpa kedipan. `Layout.tsx` membaca aturan yang sama untuk state tombol toggle; jika aturan diubah, ubah keduanya.

## 7. Halaman & Fitur

### 7.1 Login — `pages/Login.tsx`

- Satu halaman dengan toggle mode `login` / `register`.
- Validasi register (client-side): nama lengkap wajib, password minimal 8 karakter.
- Setelah register sukses: toast "cek email untuk konfirmasi", kembali ke mode login (tidak auto-login).
- Tombol "Lanjutkan dengan Google" → OAuth redirect.
- Teks "Session aktif selama 14 hari" hanya teks statis; durasi sesi diatur di dashboard Supabase, bukan di kode.

### 7.2 Dashboard — `pages/Dashboard.tsx`

Tiga `useQuery` independen (masing-masing tampil begitu selesai, di-cache):

1. **Baris bulan ini + bulan lalu** (`queryKeys.dashboardRows`): satu query `type, amount, date, category_id, category` untuk income+expense dari awal bulan lalu sampai akhir bulan ini (`fetchAllRows`). Kartu total, tren, grafik kategori, dan grafik 7 hari semuanya dihitung dari data ini di klien (`useMemo`); 7 hari terakhir selalu berada di dalam rentang tersebut.
2. **6 transaksi terbaru** (`queryKeys.dashboardRecent`), join `transaction_categories` lewat `category_id` — hanya untuk daftar Recent Activity.
3. **3 `budget_plans` terbaru** (`queryKeys.dashboardPlans`).

Selama data belum ada, tiap kartu menampilkan skeleton. Semua nominal melewati `maskAmount` (toggle sembunyikan nominal).

Yang ditampilkan:

| Elemen | Sumber | Catatan |
|---|---|---|
| Kartu "Balance" (badge "This month") | income bulan ini − expense bulan ini | ⚠️ **Bukan saldo wallet.** Hanya selisih bulan berjalan; transfer diabaikan. Aplikasi ini tidak menghitung saldo wallet (lihat §7.7) |
| Kartu "Income" / "Expense" | total bulan ini + tren % vs bulan lalu | Tren `null` → teks "First month" |
| "Spending by Category" | expense bulan ini dikelompokkan per kategori | Donut (Recharts `PieChart`) + daftar berbatang. 5 kategori terbesar + "Other (n)". Nama/warna/ikon diambil dari `categories` di `WalletCategoryContext`; transaksi tanpa `category_id` dikelompokkan menurut teks legacy `category`, atau "Uncategorized". Kategori tanpa warna memakai `FALLBACK_COLORS`. Inner layout memakai container query Tailwind (`@container`, `@lg:`) supaya donut pindah ke atas saat kartu sempit |
| "Last 7 Days" | income & expense per hari, 6 hari lalu s.d. hari ini | Bar chart (Recharts `BarChart`). Warna dari CSS variable (`var(--primary)`, `var(--border)`, `var(--muted-foreground)`, `var(--card)`) supaya terbaca di light & dark mode. Label hari `en-US`, hari ini = "Today" |
| "Active Budget Plans" | 3 plan terbaru | Tidak difilter status meski judulnya "Active" |
| "Recent Activity" | 6 transaksi terbaru | Tombol "Record Transaction" hanya `navigate('/transactions')` |

Tata letak: kartu total 3 kolom mulai `md`; area bawah 3 kolom (kiri 2/3: kategori, 7 hari, plans; kanan: Recent Activity) baru mulai `xl`, di bawahnya bertumpuk satu kolom.

Nama tampilan transaksi: `description || transaction_category.name || category (legacy) || '—'`.

### 7.3 Transactions / Activity — `pages/transactions/`

File: `index.tsx` (list + filter + delete), `add.tsx` (`TransactionAdd`, panel inline collapsible), `edit.tsx` (`TransactionEdit`, modal).

**Tipe transaksi**: `'income' | 'expense' | 'transfer'`.

**Tata letak filter**: bar filter (`sticky top-0`) menempel di atas saat daftar di-scroll, berisi pemilih bulan, pencarian, dan filter tipe. Pemilih bulan = tombol ‹ (bulan lebih lama) + `<select>` (termasuk "All Time") + tombol › (bulan lebih baru); tombol mengikuti urutan `monthOptions` (terbaru → terlama) dan nonaktif di ujung daftar atau saat "All Time". Filter income (`filterIncomeId`, hanya muncul jika bulan terpilih punya income) berada di dalam bar, di sebelah filter tipe, mulai breakpoint `xl`; di layar lebih kecil ia pindah ke baris sendiri di bawah bar dan tidak ikut menempel, supaya bar tetap pendek.

**Tombol tambah**: di desktop tombol "Add Transaction" ada di header. Di HP header hanya menampilkan "Close Form" saat form terbuka; untuk membuka form dipakai tombol bulat melayang (`aria-label="Add transaction"`, di atas bottom nav) yang juga men-scroll `<main>` ke atas karena form dirender di bagian atas halaman.

**Filter (state di `index.tsx`)**

| State | Default | Efek |
|---|---|---|
| `filterMonthYear` | bulan berjalan (`yyyy-MM`); `''` = "All Time" | `date >= yyyy-MM-01 AND date <= yyyy-MM-<lastDay>` |
| `filterType` | `'all'` | `type = ...` (tombol All / In / Out; **tidak ada tombol Transfer**) |
| `filterIncomeId` | `'all'` | `id = X OR linked_income_id = X` — menampilkan satu income beserta semua expense yang ditautkan padanya. Di-reset ke `'all'` saat bulan diganti |
| `searchTerm` | `''` | Debounce 500 ms → `description ILIKE %q% OR category ILIKE %q%` |

**Query list**: select `*, transaction_details(*), wallet:wallets!wallet_id(id,name,color), to_wallet:wallets!to_wallet_id(id,name,color), transaction_category:transaction_categories!category_id(id,name,color,icon)` urut `date DESC, created_at DESC, id DESC`. Memakai `useInfiniteQuery`; query key memuat keempat filter, jadi tiap kombinasi filter punya cache sendiri. Saat filter diganti, daftar lama tetap terlihat (diredupkan) sampai data baru datang (`keepPreviousData`).

**Pagination (infinite scroll)**: `IntersectionObserver` (rootMargin 400px) pada elemen sentinel. Satu halaman = `PAGE_SIZE` (30) baris. Tiap request meminta `range(offset, offset + 30)` = 31 baris; baris ke-31 hanya penanda bahwa masih ada halaman berikutnya (tidak ada `count: 'exact'`). Baris digabung dengan dedup berdasarkan `id`.

**Statistik (Income / Expense / Balance)**: satu `useQuery` yang mengambil `type, amount` lalu dijumlahkan di klien; mengikuti filter tipe, bulan & `filterIncomeId`, **tidak** mengikuti kata kunci pencarian. Hanya tampil **dan hanya diambil** jika filter bulan aktif.

**`linked_income` di list**: tidak di-join dari DB. Di-resolve di klien saat render (`useMemo`) dari query `monthIncomes` (daftar income pada bulan filter), jadi badge muncul begitu kedua request selesai, apa pun urutannya. Konsekuensi yang masih ada: expense yang ditautkan ke income **di bulan lain** akan punya `linked_income = null` di list (badge tautan tidak muncul).

**Tampilan list**: dikelompokkan Bulan → Hari (header "TODAY, …" / "YESTERDAY, …" / nama hari, format `en-GB` uppercase). Klik baris = buka modal edit. Baris dengan `transaction_details` punya tombol expand "N Details".

**Tambah (`TransactionAdd`)** — field per tab:

| Field | Expense | Income | Transfer | Kolom DB |
|---|---|---|---|---|
| Amount (integer, hanya digit) | ✓ wajib | ✓ wajib | ✓ wajib | `amount` |
| Wallet | ✓ wajib | ✓ wajib | ✓ wajib ("dari") | `wallet_id` |
| To Wallet | — | — | ✓ wajib, ≠ wallet asal | `to_wallet_id` |

### 7.6 Split Bill — `pages/split-bill/`

File:

| File | Isi |
|---|---|
| `index.tsx` | List bill (`/split-bill`); klik kartu → `/split-bill/:id`, tombol create → `/split-bill/new` |
| `SplitBillForm.tsx` | **Satu-satunya** editor, dipakai untuk bill baru dan edit (`bill` prop) |
| `calculate.ts` | Tipe data, rumus `calculateSplit`, konversi item ⇄ baris (`expandItems`, `groupRows`, `splitEvenly`) |
| `add.tsx` / `edit.tsx` | Halaman route: `SplitBillAdd` (`/split-bill/new`) → form kosong; `SplitBillEdit` (`/split-bill/:id`) → memuat header `split_bills` dan `split_bill_details` dari DB, `groupRows`, lalu form. Karena punya URL sendiri, refresh tetap di halaman yang sama (isian yang belum disimpan tetap hilang) |

- Fitur kalkulator patungan; **tidak terhubung** ke transaksi/wallet.

**Alur input (sejak 2026-11-22)** — dirancang untuk nongkrong ramai-ramai. Item, orang, dan pembagian ada dalam **satu kartu** "Items & who had what":

1. **Baris isian item** di bawah daftar: `{ name, qty, price (per unit) }`. Enter (atau tombol Add) menambah item ke daftar, mengosongkan baris, dan fokus kembali ke nama — jadi semua item struk bisa diketik berurutan. Harga wajib > 0.
2. **Baris orang** di atas daftar: chip nama (klik = pilih orang aktif, × = hapus) + input "Add person". Saran nama ("Recent") diambil dari `person_name` di 20 bill terakhir (`split_bills` → `split_bill_details`, diurut paling sering); tidak ada tabel teman terpisah. Nama duplikat (case-insensitive) ditolak.
3. **Daftar item**: klik baris = centang/batal untuk orang aktif (`BillItem.assignees`). Item dengan beberapa orang = **dibagi rata**; tombol "Everyone" mengisi/mengosongkan semua orang. Tombol pensil membuka mode edit inline (nama, qty, harga, ✓ simpan, × batal, hapus; Enter/Escape). Item yang belum punya orang ditandai dan **memblokir simpan**; simpan juga ditolak jika masih ada item yang sedang diedit atau isian item baru yang belum di-Enter.
4. Modifier global: Discount, Tax (PB1), Service — masing-masing `percentage` atau `nominal`; Delivery Fee & Admin Fee (nominal).

**Item → baris**: `expandItems` memecah tiap item menjadi satu baris per orang. Total item (`price × qty`) dibagi dengan `splitEvenly` menjadi rupiah bulat yang jumlahnya tepat sama dengan total (sisa pembagian +1 rupiah ke orang pertama). Baris-baris inilah input rumus dan yang disimpan ke DB.

**Algoritma (`calculateSplit` di `calculate.ts`)** — harus dipertahankan persis saat refactor (dipindah apa adanya dari add/edit lama; diverifikasi identik pada 2.000 kasus acak). Di bawah, "item" = satu baris (person, share):

```
price(item)      = originalPrice × qty
totalSubtotal    = Σ price
taxNominal       = taxType == 'percentage'      ? totalSubtotal × taxValue/100      : taxValue
serviceNominal   = (sama)
discountNominal  = (sama)
targetGrandTotal = round(totalSubtotal + taxNominal + serviceNominal + deliveryFee + adminFee − discountNominal)

numPeople        = jumlah personName unik (kosong → 'Unassigned')
ratio(item)      = price / totalSubtotal
itemTax/Service/Discount = ratio × nominal masing-masing          (proporsional terhadap harga)
itemDelivery     = (deliveryFee / numPeople) / jumlahItemOrangItu  (dibagi RATA per orang)
itemAdmin        = (adminFee   / numPeople) / jumlahItemOrangItu  (dibagi RATA per orang)
finalPrice(item) = round(price + itemTax + itemService + itemDelivery + itemAdmin − itemDiscount)
totalPerOrang    = Σ finalPrice item milik orang itu
```

Catatan: pajak & service dihitung dari subtotal **sebelum** diskon. Karena pembulatan per item, `Σ finalPrice` bisa selisih beberapa rupiah dari `targetGrandTotal`.

**Simpan**: insert `split_bills` (header, menyimpan tipe & nilai modifier) lalu `split_bill_details`, satu baris per (orang, bagian item). `original_price` di DB = **bagian orang itu dari total item** (sudah dikali qty dan sudah dibagi); `qty` **tidak disimpan**. Format kolom sama dengan sebelum redesign, jadi riwayat lama tetap terbaca.

**Edit**: `groupRows` membangun ulang item & orang dari baris tersimpan. Baris dengan `item_name` sama, harga selisih ≤ 1 rupiah, dan orang berbeda digabung kembali menjadi satu item bersama (urutan orang disusun agar pembagian ulang menghasilkan angka yang sama). Selain itu tiap baris menjadi item sendiri. Karena qty tidak disimpan, item kembali sebagai qty 1 dengan harga = total. Simpan = UPDATE header → DELETE semua detail → INSERT ulang.

**Hapus**: DELETE detail dulu, lalu header (manual, tidak mengandalkan cascade).

## 10. Konvensi yang Berlaku di Kode

- Komponen: function component, named export (kecuali `App` default export).
- Notifikasi: `toast.success/error/warning` dari `sonner`.
- Animasi: `motion` + `AnimatePresence` untuk modal/panel.
- Modal: dibuat manual (div overlay `fixed inset-0`), bukan komponen dialog bersama. Klik overlay = tutup; `stopPropagation` di konten.
- Input nominal: `<input type="text" inputMode="numeric">` + `value.replace(/\D/g, '')` (hanya digit, tanpa desimal/negatif).
- Tanggal: string `yyyy-MM-dd`. Parsing untuk tampilan memakai `new Date(date + 'T00:00:00')` agar tidak bergeser zona waktu.
- Rentang bulan: `yyyy-MM-01` s.d. `yyyy-MM-<lastDay>` dengan `lastDay = new Date(year, month, 0).getDate()`.
- Warna tipe: income = emerald, expense = rose, transfer = blue.
- Warna tema: CSS variables di `styles/theme.css` (`--primary: #059669`). Komentar di file itu: untuk ganti warna cukup fokus ke `primary`, `background`, `card`.

## 11. Masalah yang Sudah Diketahui (wajib dibaca sebelum refactor)

Daftar ini adalah perilaku **aktual** kode saat ini. Saat refactor, putuskan secara sadar mana yang dipertahankan dan mana yang diperbaiki.

### Bug / perilaku berisiko

1. **Tanggal default memakai UTC** — **sudah diperbaiki di `transactions/add.tsx`** (`todayLocal()` / `thisMonthLocal()`). Masih ada di `transactions/edit.tsx` untuk default `editIncomeMonth` (`toISOString`), yang hanya dipakai jika transaksi tidak punya tanggal tertaut.
2. **`Init.tsx` melanggar Rules of Hooks**: `useEffect` dipanggil setelah `return` kondisional (guard admin). Bisa error "Rendered more hooks…" ketika `profile` berubah dari null → admin.
3. **`AuthContext` stale closure**: callback `onAuthStateChange` menangkap `profile` saat mount (selalu `null`), sehingga `fetchProfile` dipanggil pada **setiap** event auth (termasuk `TOKEN_REFRESHED`).
4. ~~Dashboard empty-state tidak pernah muncul~~ — **sudah diperbaiki**: sekarang mengecek `allRecentTx.length === 0`.
5. **Pencarian tidak di-escape**: (a) `HighlightMatch` membuat `new RegExp(match)` dari input user → karakter seperti `(` atau `[` melempar error dan merusak render; (b) kata kunci disisipkan mentah ke filter PostgREST `.or(...)` → koma/kurung merusak query.
6. **`linked_income` hanya ter-resolve untuk income di bulan filter** (lihat §7.3).
7. **Operasi tidak atomik**: transaksi+detail, plan+item, split bill+detail. Pola delete-all-then-insert pada edit plan & split bill bisa menghilangkan data jika insert gagal.
8. **Split bill kehilangan `qty`** setelah disimpan (lihat §7.6).
9. **Edit transaksi**: `amount` di-parse `parseFloat` (add memakai `parseInt`); detail dengan amount `0` dimuat sebagai string kosong lalu dilewati saat simpan.
10. **Error ditelan**: `addWallet`/`addCategory` mengembalikan `null` tanpa pesan; `fetchProfile`, `fetchBills`, `refreshWallets` mengabaikan `error`.
11. **`MonthRangeContext.refresh()` tidak pernah dipanggil** (lihat §6.2).
12. ~~Tidak ada navigasi mobile ke Master Data~~ — **sudah diperbaiki** lewat menu More (lihat §5).
13. **Route `/init` tidak dijaga di router**, hanya di komponen. Keamanan sebenarnya bergantung RLS.
14. ~~Dark mode tidak aktif di `/login`~~ — **sudah diperbaiki** (skrip tema di `index.html`).
